Documentação da API

API REST completa para controle financeiro pessoal: autenticação JWT, CRUDs de categorias, fontes/destinos e lançamentos com parcelamento no cartão, três relatórios (por categoria, por fonte/destino, faturas futuras) e rota de saúde financeira (desafio).

Visão geral

A API foi desenvolvida com as seguintes características:

  • Sem ORM — SQL cru com mysql2 e prepared statements (?).
  • Autenticação stateless — JWT (HS256, 1h) + middleware express-jwt.
  • Isolamento total — todo SQL filtra usuario_id = req.auth.id; acesso cruzado → 404.
  • Parcelamento real — divisão em centavos, resto na 1ª parcela, grupo_parcelamento UUID.
  • Docker-first — docker compose up -d --build sobe DB + API com healthchecks.

Stack

Node.js 20+ (imagem Docker 24) · Express 4 · mysql2 · bcrypt · jsonwebtoken · express-jwt · dotenv

Base URL

  • Local: http://localhost:3000
  • Produção (deploy atual, Render): https://trabalho-backend-jrkv.onrender.com

Todos os caminhos da referência de rotas e da referência detalhada são relativos à Base URL.

Content types

  • Requisição/resposta JSON: application/json
  • Importação/modelo CSV: text/csv (modelo com BOM UTF-8)
  • Importação/exportação Excel: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet

Como subir localmente

# 1. Banco (Docker)
docker compose up -d --build db

# 2. API
cp .env.example .env
# edite .env → defina JWT_SECRET (32+ caracteres)
npm install
npm run dev

# 3. Teste
curl http://localhost:3000/health
# {"status":"ok","banco":"ok"}

Ou use docker compose up -d --build para subir banco e API juntos.

A API usa JWT (HS256, expiração de 1h). O token deve ser enviado no header Authorization: Bearer <token> nas rotas protegidas.

Referência detalhada por recurso

Cada endpoint abaixo traz parâmetros, exemplo de requisição, exemplo de resposta e um painel interativo: um exemplo de curl para testar no terminal (com botão Copiar), campos pré-preenchidos e o botão Testar, que envia a requisição e exibe abaixo o status e a resposta em JSON — também formatada em campos quando for um objeto. Todos os caminhos são relativos à Base URL. Nos exemplos de terminal, $BASE é a Base URL (ex.: http://localhost:3000) e $TOKEN é o JWT retornado por POST /auth/login. As rotas de dados são protegidas (exigem o header Authorization: Bearer <token>), exceto /auth/cadastro, /auth/login e /health.

Auth

POST /auth/cadastro Não protegida

Cadastra um usuário. A senha exige ao menos 8 caracteres, com letra e número; o CPF pode vir com ou sem pontuação. E-mail e CPF são normalizados e únicos.

POST /auth/cadastro
Content-Type: application/json

{ "nome": "Ana Souza", "email": "ana@email.com", "cpf": "529.982.247-25", "senha": "Ana@1234" }
// Resposta 201
{ "id": 1, "nome": "Ana Souza", "email": "ana@email.com" }

Erros: 400 { "erro": "Dados inválidos.", "campos": { ... } } · 409 { "erro": "Conflito.", "campos": { "email": "E-mail já cadastrado." } } (ou cpf) · 500.

POST /auth/login Não protegida

Autentica por e-mail e senha e devolve um JWT (HS256) com validade de 1h.

POST /auth/login
Content-Type: application/json

{ "email": "ana@email.com", "senha": "Ana@1234" }
// Resposta 200
{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "usuario": { "id": 1, "nome": "Ana Souza", "email": "ana@email.com" } }

Erros: 401 { "erro": "E-mail ou senha inválidos." } (mesma mensagem para e-mail inexistente e senha incorreta) · 500.

GET /auth/me Protegida

Devolve os dados do usuário autenticado (nunca inclui senha_hash).

GET /auth/me
Authorization: Bearer <token>
// Resposta 200
{ "id": 1, "nome": "Ana Souza", "email": "ana@email.com", "cpf": "52998224725", "criado_em": "2026-11-01T12:00:00.000Z" }

Erros: 401 · 404 · 500.

Importação e exportação

Importação e exportação de lançamentos em lote, sem dependências externas (utils/csv.js e utils/xlsx.js). Os endpoints estão detalhados na referência de rotas.

MétodoCaminhoDescrição
GET /lancamentos/importar/modelo Baixa o modelo de importação. Por padrão em .xlsx, com as colunas Categoria e Fonte/Destino em lista suspensa e a coluna Data com validação de calendário. Com ?formato=csv, baixa em CSV (UTF-8 com BOM).
POST /lancamentos/importar Recebe CSV (text/csv) ou .xlsx. Valida todas as linhas antes de gravar: se qualquer célula for inválida, nada é importado e a resposta lista cada erro com linha, coluna e mensagem. Categorias e fontes/destinos citados pelo nome que não existirem são criados automaticamente (retorno informa categoriasCriadas e fontesCriadas).
GET /lancamentos/exportar Baixa um .xlsx com todos os lançamentos do usuário (sem paginação), respeitando os filtros opcionais inicio, fim, tipo, categoriaId e fonteDestinoId.

Colunas do arquivo: Data, Descrição, Categoria, Fonte/Destino, Parcela, Valor. O export inclui a coluna extra Tipo, ignorada na importação (o tipo é inferido da categoria). No CSV, separador vírgula e decimal com ponto (150.90); as colunas são reconhecidas pelo cabeçalho, então a importação aceita tanto o modelo quanto o arquivo gerado por /lancamentos/exportar. Parcelamento apenas para saída em cartão de crédito.

Formato de erro

Todas as respostas de erro seguem o formato único { erro, campos? }:

StatusExemplo
400{ "erro": "Dados inválidos.", "campos": { "campo": "mensagem" } }
401{ "erro": "Token ausente, inválido ou expirado." }
404{ "erro": "Lançamento não encontrado." }
409{ "erro": "Conflito.", "campos": { "campo": "mensagem" } }
500{ "erro": "Erro interno do servidor." }

Nota: a forma { erro, campos? } é constante, mas a mensagem de erro varia conforme o recurso. Exemplos reais: 409 → "Conflito." (cadastro duplicado), "Categoria já cadastrada." (categorias) ou "Fonte/destino já cadastrado." (fontes/destinos); 404 → "Lançamento não encontrado.", "Categoria não encontrada.", "Fonte/destino não encontrado.", "Usuário não encontrado." ou "Rota não encontrada." (rota inexistente).

CORS

A origem permitida é https://SEU_USUARIO.github.io (apenas scheme://host, sem o caminho do repositório).

Configuração no backend (produção)

Defina a variável de ambiente CORS_ORIGIN no backend (Render):

CORS_ORIGIN=https://SEU_USUARIO.github.io

Em desenvolvimento local: http://localhost:4200,null,https://SEU_USUARIO.github.io (o null cobre a demo aberta via file://).

Saúde financeira (desafio)

Aviso: Informações educativas; não constituem recomendação financeira profissional.

Rota: GET /saude-financeira (protegida). Calcula 11 indicadores + projeção de 6 meses + dicas com limiares fixos, baseados nos lançamentos do usuário.

Indicadores e projeção

IndicadorFórmulaSaída / Limiar de dica
taxaPoupanca(entradas - saidas) / entradas (0 se entradas=0)4 casas — dica se < 10%

Janela base

Entradas/Saídas base: mês corrente + 2 anteriores (janela de 3 meses via helpers UTC); média mensal = total/3. Média anterior (fora da curva): 3 meses completos anteriores (m−3-01 … m−1-último-dia).

Regras de dicas (máximo 8; 1 positiva se nenhuma disparar)

  1. taxaPoupanca < 0.10
  2. comprometimentoCartoes > 0.30
  3. mesesDeReserva < 3
  4. Categoria do mês: mediaAnterior>0 e ratio > 1.30
  5. Projeção: algum mês com saldoPrevisto < 0
  6. indiceEndividamento > 0.15
  7. runwayMeses < 3
  8. indiceConcentracao > 0.60
  9. tendenciaGastos.direcao === 'alta' (variação ≥ +10%; a direção baixa não gera dica)
